# Repository guidance

## Architecture

- Treat this repository's `master` branch as the source of truth. `chezmoi-master` is migration history only.
- Keep every globally available tool in Nix and Home Manager: the base environment, language servers, linters, formatters, everyday CLIs, and the fallback language runtimes. `flake.lock` is what pins them.
- Keep mise for per-project version switching plus the vendor CLIs that must track upstream weekly (`claude`, `cloudflared`, `aqua:openai/codex`, `herdr`). Declare project runtimes in that project's own `mise.toml` or idiomatic version file, never in the global toolset.
- Keep ordinary dotfiles in `mise/`.
- Keep update orchestration in `.dotflow.toml` and `scripts/`; do not duplicate it in shell startup files.
- Preserve the environment split: shared `unix` for macOS and WSL, `darwin` for macOS-only dotfiles (karabiner, rio), and `windows` for the complete native Windows environment including PowerShell.

## Changes

- Read the relevant profile and its source dotfile before editing.
- Add globally available tools to `nix/home.nix`. Its `devTools` / `debugTools` / `cliTools` / `runtimes` lists are the single source of truth for them.
- A tool must never be declared in both `nix/home.nix` and the global mise toolset. mise prepends its install directories ahead of the Nix profile, so mise silently wins and the Nix entry becomes dead weight.
- Sheldon activates mise with `mise activate zsh` (PATH activation), not `--shims`. Shims abort with `No version is set for shim: <tool>` instead of falling through to the Nix profile, which would break every fallback runtime. Keep `wsl-local-bin` ordered before the mise plugin so `~/.local/bin` survives in `__MISE_ORIG_PATH`.
- Put the remaining shared macOS/WSL mise entries in `mise/dotfiles/mise/config.unix.toml`. It is the single source of truth and is symlinked to `~/.config/mise/config.toml`, so never duplicate the toolset in `mise/mise.unix.toml`. Editing it takes effect immediately, so land the matching Nix change first.
- Put shared macOS/WSL dotfiles in `mise/mise.unix.toml`; keep only OS-specific entries in `mise.darwin.toml` (currently karabiner and rio).
- Put Windows tools in `mise/dotfiles/mise/config.windows.toml`. It is the single source of truth and is copied to `~/.config/mise/config.toml`, so never duplicate the toolset in `mise/mise.windows.toml`.
- Do not add project-only tools such as `bun` or `uv` to the global toolsets.
- Write nested values in `mise/dotfiles/ai/codex/config.toml` as dotted keys (`tui.status_line = [...]`), never as `[table]` headers. `scripts/sync-ai-config.sh` puts the managed block at the top of `~/.codex/config.toml` and keeps the machine-local settings below it, so a table header would swallow every top-level key that follows. The script refuses to run when the source has a table header, and it drops body keys by reading the source's own top-level key names, so adding a default there needs no change to the script.
- `scripts/sync-takumi-guard.sh` is the single source of truth for the Takumi Guard registry settings, and `.dotflow.toml` re-applies it on every `dotflow update`. Everything it writes — `~/.npmrc`, `~/.bundle/config`, `~/.netrc`, pip's `pip.conf`, and `~/.config/uv/uv.toml` — carries the `tg_anon_` token, so those files stay machine-local: never add them to the mise dotfiles or to the repository. It writes through each tool's own command (`npm config set`, `bundle config set --global`, `go env -w`) so that unrelated keys survive, and it owns `pip.conf` / `uv.toml` only while their first line is its marker. `bundle config get` in Bundler 4 rejects `--global` and also reads the cwd's `.bundle/config`, so the idempotence check reads `~/.bundle/config` directly.
- rio is the terminal on macOS and Windows; it only draws, and herdr owns splits, tabs, workspaces, and session persistence, so `mise/dotfiles/.config/rio/config.toml` disables rio's own tabs and splits. One config serves both OSes: OS-specific values go under `[platform.macos]` / `[platform.windows]`, which can override only shell, window, navigation, renderer, env-vars, and theme (`rio-backend/src/config/platform.rs`) — never fonts. On Windows rio starts herdr inside WSL through `wsl.exe --exec zsh`, and pwsh is run as `pwsh.exe` from WSL. rio comes from the Homebrew cask on macOS (nixpkgs, stable and unstable, still ships 0.4.7) and from winget (`raphamorim.rio`) on Windows. Its man page `rio(5)` is stale — it lists `fonts.extras`, which v0.5.29 does not have, and omits `[hints]` — so check key names against `rio-backend/src/config/` for the installed version. rio passes `window.background-image.path` straight to the image decoder without expanding `~`, which is why both platform paths are absolute.
- rio cannot scale or offset individual fonts, so a `fonts.symbol-map` fallback (such as Hiragino for Japanese) renders at a different height from the Latin font. Use a composite font whose Japanese glyphs share the Latin metrics: `Moralerspace Neon` (Monaspace + IBM Plex Sans JP + Nerd Fonts), from `pkgs.moralerspace` in `nix/darwin.nix` on macOS and installed by hand on Windows because winget does not carry it (see README).
- herdr's prefix is `ctrl+q`. rio turns Ctrl+Shift+T / Ctrl+Shift+W / Ctrl+1..9 into herdr prefix sequences (`esc = "\u0011..."`), because the legacy key encoding cannot tell Ctrl+1 from 1 or Ctrl+Shift+T from Ctrl+T; change `prefix`, `new_tab`, `close_tab`, or `switch_tab` in `herdr/config.toml` together with those bindings. `mise/dotfiles/.config/herdr/scripts/copy-last-output.sh` (`prefix+c`) finds the previous command's output by walking rows: it skips the current prompt block up to the blank line `add_newline` emits, then looks for the preceding line starting with `❯`. That symbol and the three-line prompt shape come from `mise/dotfiles/.config/starship.toml` (`format`, `add_newline`, `[character]`), which stays the single source of truth — change the script with it; `copy-last-output.sh --stdin` runs the parser alone for testing. herdr writes back to `~/.config/herdr`, so `mise.unix.toml` links only `config.toml` and `scripts/`. Do not run `herdr integration install` for claude or codex: it writes absolute paths into `~/.claude/settings.json`, which is a symlink into this repository, and into `~/.codex`. The integrations are vendored instead: the hook scripts herdr generates live at `mise/dotfiles/ai/claude/hooks/herdr-agent-state.sh` and `mise/dotfiles/ai/codex/herdr-agent-state.sh`, `settings.json` and `codex/hooks.json` call them through `~`, and `codex/config.toml` sets `features.hooks = true`. After a herdr upgrade, if `herdr integration status` reports them outdated, regenerate them with `CLAUDE_CONFIG_DIR` / `CODEX_HOME` pointed at a scratch directory and copy the scripts over. Agent notifications come from herdr's own state detection, so Claude Code and Codex keep their default notification settings.
- Do not track credentials, OAuth state, histories, sessions, caches, generated memories, installation IDs, or machine-local trust decisions.
- Preserve unrelated worktree changes and avoid destructive Git operations.

## Validation

- Run `nix flake check --no-build` after Nix or Home Manager changes. It only evaluates, so it cannot catch `buildEnv` filename collisions between two packages; build the profile as a dry run to catch those: `nix build --no-link '.#darwinConfigurations."uvu1-mac".config.home-manager.users.uvu1.home.path'`.
- Regenerate the shim directory after removing anything from the global mise toolset (`rm -rf ~/.local/share/mise/shims && mise reshim`). `mise reshim` alone keeps orphans and `mise prune` only removes installed versions, so a stale shim would shadow the Nix profile.
- Run the relevant `mise -C mise -E <env> dotfiles status` after dotfile changes (`unix`, `darwin`, or `windows`).
- Run `mise/dotfiles/ai/scripts/check-ai-config.sh` after AI configuration changes.
- Run `bash scripts/sync-takumi-guard.sh --dry-run` after changing that script, then run it twice for real: the second run must print `Takumi Guard already configured`. Anything else means one target's idempotence check is wrong. Use a throwaway `HOME` to exercise it without touching the machine.
- Run `herdr config check` after herdr config changes; it reports conflicting and invalid keybindings. Use a throwaway `HOME` to check an uncommitted copy.
- Use `dotflow doctor` to validate dotflow configuration. `dotflow update --dry-run` requires a clean worktree.
