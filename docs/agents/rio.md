# rio

- rio is the terminal on macOS and Windows; it only draws, and herdr owns splits, tabs, workspaces, and session persistence, so `mise/dotfiles/.config/rio/config.toml` disables rio's own tabs and splits. One config serves both OSes: OS-specific values go under `[platform.macos]` / `[platform.windows]`, which can override only shell, window, navigation, renderer, env-vars, and theme (`rio-backend/src/config/platform.rs`) — never fonts. Windows therefore renders its config through `config.windows.toml.tmpl` (a `template` entry in `mise.windows.toml`), which reads `config.toml` and replaces its single `size = 16`; the template throws if that line is missing or duplicated, so change both files together. On Windows rio starts herdr inside WSL through `wsl.exe --exec /home/uvu1/.nix-profile/bin/zsh`; `--exec` skips the shell and searches WSL's default PATH, where the Nix-provided zsh does not exist, so a bare `zsh` makes the pane exit at once and rio close. rio on Windows also joins `shell.args` with spaces without quoting (`create_pty` in `teletypewriter/src/windows/mod.rs`, unchanged through v0.5.29), so an argument containing spaces must carry its own `"…"` or zsh receives only its first word. pwsh is run as `pwsh.exe` from WSL. rio comes from the Homebrew cask on macOS (nixpkgs, stable and unstable, still ships 0.4.7) and from winget (`raphamorim.rio`) on Windows. Its man page `rio(5)` is stale — it lists `fonts.extras`, which v0.5.29 does not have, and omits `[hints]` — so check key names against `rio-backend/src/config/` for the installed version. rio passes `window.background-image.path` straight to the image decoder without expanding `~`, which is why both platform paths are absolute.
- rio cannot scale or offset individual fonts, so a `fonts.symbol-map` fallback (such as Hiragino for Japanese) renders at a different height from the Latin font. Use a composite font whose Japanese glyphs share the Latin metrics: `Moralerspace Neon` (Monaspace + IBM Plex Sans JP + Nerd Fonts), from `pkgs.moralerspace` in `nix/darwin.nix` on macOS and installed by hand on Windows because winget does not carry it (see README).
- rio sends Alt+[ / Alt+] as kitty CSI u (`\u001b[91;3u` / `\u001b[93;3u`) through `esc` bindings, because the legacy encoding turns them into `ESC [` / `ESC ]`, which herdr and nvim read as the start of a CSI / OSC sequence. nvim maps `<M-[>` / `<M-]>` to `:bprevious` / `:bnext` (`nvim/lua/config/keymaps.lua`); change both together.
